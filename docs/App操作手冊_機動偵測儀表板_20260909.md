## 一、系統定位

以公開 TLE（Two-Line Element）資料為輸入，對單一衛星或整個星系進行**機動（軌道變化）候選事件**偵測的 Streamlit 儀表板。整合三層方法：

1. **規則式策略層**（P1–P6）：高度/F10.7 自適應閾值、單調衰減抑制、B* 輔助抑制等人工設計規則。
2. **統計偵測層**：CUSUM（累積和）、BOCPD（貝式線上變點偵測）、SSA（奇異譜分析，非「太空態勢感知」）。
3. **機器學習層**：LightGBM 監督式分類（Model 1，40 特徵）＋ Isolation Forest 無監督異常偵測（Model 2，regime-agnostic，可處理非 Starlink 任意軌道）；兩者由 HistGBM 融合評分器整合。

所有方法皆須先扣除**大氣阻力造成的自然軌道衰減**才能看清真正的機動訊號，這由 `atmospheric_drag.py`（NRLMSIS 物理阻力殘差模型）負責，見第五節。

## 二、啟動方式

### 2.1 本機執行

```bash
streamlit run maneuver_app_2026September.py
```

**資料後端二選一（啟動時自動判斷）**：

| 模式 | 觸發條件 | 說明 |
|---|---|---|
| 本機全庫 | 未設 `HF_DATASET_REPO` 環境變數，且本機存在 `space_db.duckdb` | 直接讀本機 14GB 全庫，功能與速度皆最完整 |
| HF 遠端 Parquet | 設有 `HF_DATASET_REPO=<帳號>/<repo>` | 啟動時自動安裝 DuckDB httpfs extension，建立指向 `hf://datasets/...` 的輕量 stub DB；免下載整庫，但首次查詢單顆衛星約需數秒（冷點約 10–16 秒，之後有 `@st.cache_data` 快取） |

已發布之正式版：`https://huggingface.co/spaces/RhynoWu/maneuver-detection`（docker SDK，`app.py` 進入點，`runpy` 每次重跑 `maneuver_app_2026September.py`）；三語展示版：`https://rhynowu-maneuver-detection-i18n.hf.space`。

**注意**：正式版 Space 目前處於 **PAUSED**（HF 免費額度休眠），需要展示前先到 Space 頁面按 Restart 喚醒。

## 四、頁首 KPI 卡片列（2026-09-09 新增）

進入系統立即可見，不需查詢特定衛星即顯示，涵蓋**全艦隊（284 顆 MEME-truth Starlink，`data/url_registry.csv`）**：

| 卡片 | 意義 | 資料來源 | 注意事項 |
|---|---|---|---|
| 近 30 天機動事件數 | medium/large 等級機動之 episode 數（同顆衛星間隔 >48h 才算新事件） | MEME 精密星曆真值（`data/meme_truth/transitions_full_*.csv`） | **若真值資料本身滯後超過 30 天，卡片顯示「—」並附註最新真值日期**，避免誤讀成「近期無機動」 |
| 資料品質 good 比例 | 近 30 天艦隊 TLE 逐筆稽核（`data_quality_audit.py`）之 good 比例 | 全艦隊近 30 天原始 TLE，逐顆分別稽核後彙總 | rejected 通常是 checksum/物理不可能值；suspect 常見原因是資料缺口（gap）或傾角跳變 |
| 疑似離軌顆數（da_monotonic_decay） | 近 7 天窗內判定為「純大氣阻力衰減」（非機動）之顆數 | 全艦隊近 30 天 TLE，套用 `frac_neg≥0.85 且無>2km跳變且bstar>0且淨Δa<-2km` | 此為**純被動衰減**判定，與「主動控制離軌」（SatDashboard `/starlink-deorbit` 之判定邏輯）是互補而非重複的兩套指標，兩者交集通常很小甚至為 0（見 `docs/驗證_da_monotonic_decay_vs_離軌啟發式_20260909.md`）——不要把兩者當作同一件事的兩種算法互相校驗 |

三卡皆有 `@st.cache_data(ttl=3600)` 快取，一小時內重新整理頁面不會重複查詢資料庫。

## 五、逐區塊操作與判讀說明

### 5.1 側邊欄查詢與參數

- **NORAD ID / 名稱 / wildcard**：可輸入 NORAD ID（如 `57681`）、完整衛星名稱、或萬用字元（`STARLINK-30*`、`SL-1?`）。
- **P2 高度自適應閾值（拋物線左側）**：`P2 vertex 高度`（400–1000km，預設700）、`P2 floor 閾值`（0.1–1.0km，預設0.4）、`P2 @400km 閾值`（0.5–4.0km，預設2.0）——這三個參數共同定義「多低的高度、多大的 Δa 才算機動」的拋物線曲線，高度愈低（阻力愈強）容許的自然波動閾值愈寬鬆。
- **P5 F10.7 自適應倍率（拋物線）**：`P5 vertex F10.7`（50–120sfu，預設70）、`P5 @200sfu 倍率`（1.0–3.0，預設1.6）——太陽活動愈強（F10.7 愈高），大氣阻力愈強，此參數放寬對應閾值以避免太陽極大期誤報。
- **SSA-RAG 知識庫**：連線位址（預設 `http://127.0.0.1:8000`）＋「執行後自動送 RAG 解說」勾選框，勾選後每次跑完 ③ 偵測會自動請 RAG 服務生成白話解說。

### 5.2 統一偵測摘要

依查詢衛星的**軌域**自動路由至對應偵測模型（`orbit_anomaly_detector.py`）：Starlink LEO → Model 1（LightGBM）+ 融合評分器；非 Starlink／衰減軌 → Model 2（regime-agnostic）+ NRLMSIS 物理主判；再入狀態 → 物理閘門直接抑制（見 §5.7）。卡片顯示：軌域·域、路由主判定、融合旗標次數、Model 2 異常次數。

### 5.3 ① 軌道根數連續變化與差值

最直觀的視覺化區塊。左上圖可切換「半長軸 a」或「離地高度」，可對照 Δa／傾角 i／Δi 等時序子圖；圖上：
- **綠色星號** = NRLMSIS 物理主判定的機動候選（見 §5.7）
- **紅色叉號** = P1–P6 規則合併判定的機動候選
兩種標記並列展示，體現「多重方法交叉驗證」的設計思路。**務必向使用者強調**：這些都是「候選」而非「已確認」機動，需配合公開發射報導或其他獨立資料源交叉比對才能提升信心度。

### 5.4 ② P1–P6 策略：個別 vs 合併

展開後可見 P1–P6 各策略之角色說明（三語皆有）：部分負責偵測（如高度自適應閾值 P2、F10.7 自適應倍率 P5），部分負責抑制誤報（如單調衰減抑制、B* 輔助抑制），最終合併為單一判定。

### 5.5 ③ 統計偵測層（CUSUM/BOCPD/SSA）＋ ML 偵測/預測

三張統計圖（累積統計量／短期異常機率／重構殘差 z-score），為獨立於規則式策略之外的第二道判讀方法；下方另有 ML forecast（未來 1 天內出現機動之機率）與 Model 2 異常標記。

### 5.6 ⑤ MEME vs TLE（僅 72h 模型）

比對 MEME 精密星曆真值與公開 TLE 的差異，**僅做 72 小時窗內模型，不做長時程外推**（外推誤差會隨時間發散，超出可信範圍）。

### 5.7 ⑥ 資料品質稽核（quality_flag：good / suspect / rejected）

對當前查詢衛星的 TLE 序列逐筆稽核，rejected=物理不可能值（NaN、離心率越界、半長軸越界、傾角越界、checksum 錯）；suspect=存疑（資料缺口過大、傾角單步跳變過大、bstar 絕對值異常）；其餘為 good。**注意**：此稽核邏輯依賴同一衛星前後 epoch 的時序差分，不可對多顆衛星混合的 DataFrame 直接呼叫（會把不同衛星的邊界誤判為異常缺口）——批次稽核須逐顆分別呼叫再彙總，頁首 KPI 卡片列已依此正確實作（見 §4）。

### 5.8 ⑦ 星系級異常分析（軌道面 Δi std／批量機動／陣型誤差）

`constellation_anomaly.py`，可指定星系（Starlink／OneWeb／千帆／Yaogan／Gaofen／Jilin），計算軌道面傾角標準差、批量部署/機動事件日、陣型相位離群。三個中國遙感星系（Yaogan/Gaofen/Jilin）之 30 天常態基線皆為 0 異常，可作為對照基準。

### 5.9 ⑧ SSA-RAG 知識問答

連線本機或遠端 SSA-RAG 服務（需另行啟動 `scripts/ask.py --chat-listen`），可用自然語言詢問系統方法論、術語解釋等問題。回答內容固定中文。

### 5.10 ⑩ 合成 TLE 批次生成

展開後可設定衛星數、天數、TLE 間隔、含機動比例、高度範圍等參數，批次生成含真實特徵（含雜訊）之合成 TLE 資料集，供演算法測試或訓練資料擴增使用（`synthetic_tle` 模組）。

### 5.11 ④ 艦隊級統計（284 顆）+ 95% 信賴區間 —— 目前隱藏

程式碼中存在（`_SHOW_FLEET_STATS = False`，2026-07-14 使用者要求隱藏以精簡頁面，**非資料有誤**），如需重新顯示，將此旗標改回 `True` 即可；其計算邏輯（bootstrap 95% CI 之艦隊機動事件率）與頁首 KPI 卡片列（§4）的「近30天機動事件數」共用同一份真值資料，兩者可互相對照。

## 六、技術背景：NRLMSIS 大氣阻力殘差（供技術教學使用）

機動偵測的核心挑戰是**先扣除大氣阻力造成的自然軌道衰減**，才能看清真正的機動訊號。原理：

```
近圓軌道阻力衰減率：  da/dt = -B · ρ · √(μ a)
逐衛星自我校準：      B_eff = median( -Δa_i / s_i )   （中位數穩健，排除機動離群）
阻力殘差：            drag_resid_da_i = Δa_i + B_eff · s_i
    純大氣衰減 → 殘差 ≈ 0；機動 → 殘差 = 機動 Δa
```

密度 ρ 由 NRLMSIS 模型（`pymsis`）依 F10.7／Ap 太陽地磁指數逐時計算；偏心軌道另以 King-Hele 幾何因子在**近地點高度**取密度（非平均高度），並以 `is_reentry_decay()` 守門排除極端 HEO 再入之非線性衰減（避免誤報）。

**2026-09-09 改善**：Ap 指數改採 NRLMSISE-00 標準 3 小時解析度 ap(7) 陣列（原為每日均值重複 7 次），密度計算之經緯度改用 SGP4 解出的星下點實際座標（原為固定 0/0）。此改善效益集中於**地磁暴時窗**（平靜期新舊版差異在噪音範圍內），已於 2024-05-11 Gannon 磁暴日驗證機制正確生效。詳見 `docs/期末報告_MEME_TLE_20260909_骨架.md` §6.x。

## 八、常見問題與已知限制

1. **「近30天機動事件數」顯示「—」而非數字**：代表 MEME 真值資料本身已滯後超過 30 天，不是系統故障，也不代表「近期沒有機動」——請參考卡片下方標註的真值最新日期。
2. **HF 遠端模式首次查詢很慢（10–16 秒）**：屬正常現象（冷讀取遠端 Parquet 檔），之後有快取加速；如需長期穩定低延遲，建議改用本機全庫模式。
3. **「疑似離軌顆數」與 SatDashboard 的離軌名單數字對不上**：這是設計上的預期行為，兩套指標分別捕捉「純被動衰減」與「快速降軌（多伴隨主動控制事件）」兩種不同的衰減型態，交集本就可能很小，詳見 §4 表格說明。
4. **所有偵測結果皆為「候選」而非「已確認」**：需要精密星曆或多來源交叉驗證才能真正確認一次機動事件；對外呈現時建議延續保守用語（例如「旨在降低誤判風險」而非「絕不會誤判」）。
5. **SSA 一詞的歧義**：本系統中 SSA 專指統計方法「奇異譜分析」（Singular Spectrum Analysis），並非「太空態勢感知」（Space Situational Awareness）的縮寫，教育訓練時建議主動澄清避免混淆。
