# L1 與 L3 數字重算與勘誤（2026-09-21；2026-09-29 補充）

> 適用文件：《期末報告》§13.2 表 13-3 與相關段落、《技術附錄》同節、《決策版》若引用 L1／L3 成績處。
> 本文件為**重算結果與勘誤的權威來源**；原報告內文未逐處改寫，僅在表 13-3 後加上指向本文的勘誤說明。

## 一、為什麼要重算

1. **L1 規則有缺陷，已修正。** P1「衰減抑制」與 P3「B* 抑制」以「小幅負 Δa」判斷大氣衰減，容許值（P1 為 2 km、P3 為 1.5 km）遠大於 P2 高度門檻，
   會把**向下的降軌機動**當成衰減擋掉。實例：福衛五號（42920）2026-04-14 的 −519 m 降軌被 P1 擋掉（該星超過門檻的 8 次轉換中，唯一被抑制者）；
   Starlink 48881 有 3/9 個 −760～−930 m 大降被 P3 擋掉。修正：本身已超過 P2 高度門檻的步階不得被 P1／P3 抑制（`maneuver_strategies_july.py`，commit `4754712`）。
2. **L3 改版。** 原「Starlink 滑動窗／單元級 L3」只以 Starlink 訓練、特徵未 σ 正規化，對福衛五號等非 Starlink 衛星無法泛化。
   改為「**候選確認式 L3**」並**依族群自動選模型**（`l3_candidate.py`、`train_l3_altimetry.py`、`train_l3_starlink.py`）。

## 二、最重要的說明：舊數字與新數字為什麼差這麼多

**差異絕大部分來自資料，不是來自修正。** 本專案的 TLE 資料庫為**滾動視窗**：報告表 13-3 為 2026-08-03 的快照（597 個正 unit／5,138 個負 unit），
今天的資料庫 Starlink 只涵蓋約 2026-03-31～09-20，MEME 真值檔亦更新（`transitions_full_20260918`），共 2,929 個正 unit／7,587 個負 unit。
**舊快照已無法在現有資料庫上重現**，因此新舊絕對數字**不可直接比較**。

要單獨看「L1 修正」的效果，必須在**同一份資料**上前後各量一次（下表，擂台 10,516 個 unit）：

| L1 指標 | 修正前 | 修正後 |
|---|---|---|
| 精確率 | 0.3723 | 0.3721 |
| 召回率 | 0.0826 | 0.0864 |
| 誤報率（FPR） | 0.0538 | 0.0563 |
| large 機動召回 | 0.1574 | 0.1621 |
| 旗標總數 | 650 | 680 |

結論：修正使 L1 召回略升、誤報略升、精確率不變，**影響很小**；報告中 L1 由 0.251 變成約 0.09 的落差，主因是資料庫視窗縮短，而非規則修正。

| 方法 | 精確率 | 召回率 | F1 |
|---|---|---|---|

**解讀（如實）**：

- **非 Starlink**：L3 的「確認」有實質增益——相對「候選全接受」，精確率由約 0.09 升至 0.41、F1 由約 0.17 升至 0.43，也高於 L2 最佳單通道（BOCPD 0.37）與 L1（0.12）。
  但 F1 0.43 並不高，即使在同分布的測高衛星上仍有相當比例的誤報與漏報。
- **Starlink**：L3 的確認**幾乎沒有增益**（0.369 對 0.366）。MEME 真值中 medium 以上的機動幾乎每天都有，約 69% 的候選本來就是正例，沒有多少可否決的空間；
  三層在 Starlink 上召回都低。這反映 Starlink 站位保持機動的高頻，不是模型故障。
- **福衛七號（樣本外，弱真值）**：**L1 規則的 F1（0.23）高於 L3（0.19）**。約 550 km 的福衛七號較接近 Starlink 的情境，泛化不如高軌測高衛星；
  且其真值為推估而非操作方認證，數字宜審慎看待。
- **福衛五號 2026-04-14 的 −519 m 降軌**：新 L3 機率約 0.84，**被確認**（舊 Starlink 滑動窗 L3 僅約 0.10）；L1 修正後也會標記。

## 七、2026-09-29 補充勘誤：阻力通道缺值洩漏

**結論**：第三節表中 L3 的 AUC 0.902 被高估。擂台的第五通道「NRLMSIS 阻力殘差」讀自 `data/drag/drag_resid_20260714.csv`，
該檔只涵蓋到 2026-07-14；之後的單元查不到阻力值，程式補 0。由於正 unit 有 79.6% 落在 07-14 之後、負 unit 只有 49.7%，
「阻力缺值」本身就成為與標籤相關的時間訊號（單獨使用 AUC 0.647），L3 學到的是這個假訊號而非阻力物理。

**對照**（同一份 2026-09-28 資料庫、同一真值，只更換阻力檔；新檔 `drag_resid_20260928.csv` 涵蓋全期，缺值占比 0.1%／1.2%）：

| 指標 | 舊阻力檔（至 07-14） | 新阻力檔（全期） |
|---|---|---|
| L3 融合評分器 OOF AUC | 0.891 | **0.812** |
| L3 不含阻力通道（12 維） | 0.798 | 0.797 |
| L3 召回（FPR≤0.05） | 0.534 | **0.475** |
| L3 large／medium／small 召回 | 0.681／0.514／0.150 | 0.641／0.430／0.100 |
| 基線「僅阻力模型」AUC | 0.381 | 0.627 |
| 融合評分器 `fusion_scorer.py` ROC-AUC | 0.891 | 0.811 |

- 舊檔帶來的約 +0.09 幾乎全是洩漏；真正的阻力物理只貢獻約 +0.013。第三節「僅阻力模型 0.353」低於 0.5，也是同一原因。
- **排序結論不變**：L3（0.812）> L2 最佳單通道 CUSUM（0.678）> L1（召回 0.086）。
- **不受影響**：候選確認式 L3（第四節）不使用阻力通道；Model 2（IsolationForest）之 IDS 域外誤報率維持 0.032（逐窗）。
