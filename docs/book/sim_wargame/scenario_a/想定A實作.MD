## 1. 摘要

依美國國防情報局（DIA）《Challenges to Security in Space 2026》繁中譯本描述的灰色地帶手法，在既有兵棋中加入想定 A。原本的海纜中斷情境保留，再加上三件事：

1. 開戰前惡意軟體抹除商用終端，參考 2022 年 Viasat 事件。
2. 商用低軌開場即被干擾，紅方把商用終端視為合法目標。
3. 網攻造成永久損失，不再是 2 回合後自動恢復。

推演結果：與同樣擁有 1,000 套商用終端的對照組相比，藍方 8 回合平均頻寬可用率下降 1.7 到 3.2 個百分點，前 3 回合跌得最多。每組 500 局，95% 信賴區間約 ±0.4 個百分點。

**不是來自 DIA 的部分**

- 海纜中斷是遊戲原有設定，DIA 2026 報告沒有討論海底電纜。
- 把俄烏案例移植到台灣周邊，是推演假設。
- 效果數值是示意值。

## 3. 規則變更

| 項目 | 原始想定 `base` | 想定 A `a` | 示意參數 |
|---|---|---|---|
| 開場低軌終端 | 0 套 | 1,000 套（20 單位） | `A_PRE_TERMS = 1000` |
| 開戰前抹除 | 無 | 藍方行動前永久抹除 30%，只能重新部署 | `A_WIPE = 0.3` |
| 開場干擾 | 無 | 第 0 回合起干擾 25%，持續 2 回合，升級 +2 | 25%、2 回合 |
| 紅方 AI 干擾門檻 | 藍方終端超過 800 套 | 藍方有終端就干擾 | 0 套 |
| 網攻未強化的閘道站 | 低軌容量減半 2 回合後恢復 | 永久抹除 30% 已部署終端 | `A_WIPE = 0.3` |
| 閘道站強化 | 擋網攻 | 擋之後的網攻，**擋不住開場抹除** | — |

其餘規則不變：8 回合（每回合 6 小時）、每方 5 行動點、開場約三成國際海纜與馬祖海纜中斷、需求 150 單位起每回合 +5、白方事件、計分方式。

### 分析用變體

這些變體只供蒙地卡羅分析，介面不顯示。

| 代號 | 內容 | 用途 |
|---|---|---|
| `a_pre` | 只有 1,000 套預置終端，其餘同原始想定；紅方干擾門檻 0 套 | 對照組；攻擊代價 = `a − a_pre` |
| `a_nojam` | 想定 A 去掉開場干擾；紅方干擾門檻與想定 A 相同（0 套） | 拆解 |
| `a_nocyber` | 想定 A 去掉開場抹除，網攻回到「減半 2 回合」 | 拆解 |

不直接和 `base` 比，是因為 `base` 沒有預置終端，比較時會把「多了終端」和「被攻擊」混在一起。

開場邏輯摘錄：

```rust
if w.is_a() {
    w.leo_terms = A_PRE_TERMS;                       // 商用終端開戰前已在使用（DIA p.37）
    if w.a_cyber() {                                 // 入侵前惡意軟體攻擊（p.43、尾註 621）
        let lost = w.leo_terms * A_WIPE;
        w.leo_terms -= lost;
        w.cyber_lost += lost;
    }
    if w.a_jam() {                                   // 商用星座開場即被干擾（p.4、37、43）
        w.jam = 0.25;
        w.jam_until = 2;
        w.escalation += 2.0;
    }
}
```

## 7. 推演結果摘要

完整表格、判讀與限制見[推演報告](推演報告_想定A灰色地帶.md)。

| 藍方打法 | 對照組 `a_pre` | 想定 A | 攻擊代價 | 前 3 回合（對照 → A） | 網攻累計抹除 |
|---|---|---|---|---|---|
| 均衡 | 86.9% | 83.7% | −3.2 | 89.4% → 85.0% | 300 套 |
| 重 GEO | 88.4% | 86.7% | −1.7 | 98.2% → 96.6% | 525 套 |
| 重低軌 | 73.4% | 71.5% | −1.9 | 85.4% → 80.4% | 300 套 |
| 重修纜 | 81.6% | 79.4% | −2.1 | 78.2% → 75.4% | 502 套 |

表中為紅方灰色地帶策略的結果；紅方升級策略下的攻擊代價為 −1.7 到 −3.1，結論相同。

**判讀時要注意的模型現象**

- 修正前，「A 去掉開場干擾」比對照組還高（88.5% 對 86.9%），原因是該變體的紅方干擾門檻仍是 800 套。2026-11-22 統一門檻後降為 84.4%，低於對照組，見第 11 節。
- 重 GEO 打法最穩，是因為遊戲中 GEO 不會被干擾或網攻；真實的 Viasat KA-SAT 就是 GEO 服務。
- 紅方升級策略下藍方可用率反而較高，原因是反衛星試射花掉 4 個行動點。這是原始模型就有的特性。

## 8. 已知限制

1. 1,000 套、30%、25% 都是示意值；DIA 的 5 萬名使用者是事件規模，不是比例。
2. Viasat 的抹除對象是 GEO 服務的數據機，遊戲套在低軌終端上，是為了讓干擾與抹除打在同一個資源上。這是簡化。
3. 雙方 AI 都是固定規則，結果是「這組規則下」的比較。
4. 只跑了一組參數，沒有做敏感度分析。
5. `a_pre` 的開場紀錄仍會顯示「紅方宣稱商用終端是合法目標」這句文字，但不影響數值；它只用於蒙地卡羅分析，介面不會出現。

## 11. 修訂紀錄：統一紅方干擾門檻（2026-11-22）

**問題**（外部審查意見 P0）：干擾門檻原本寫成 `if self.a_jam() { 0.0 } else { 800.0 }`。`a_jam()` 只在 `a`、`a_nocyber` 為真，所以 `a_pre` 和 `a_nojam` 的門檻仍是 800 套。`a_nojam` 開場被抹掉 300 套後只剩 700 套，紅方就不干擾，使「去掉開場干擾」的結果混入了紅方規則差異。

**修正**：[L444](../../../../RUST_SatDashboard/src/games_war.rs#L444) 改為 `if self.is_a() { 0.0 } else { 800.0 }`，A 系列四組共用同一條紅方規則。原始想定與 B、C、D 仍是 800 套。只改一行程式（註解併在同一行），所以其他行號不變。

**重跑**：同一組種子（1000–1499）、每組 500 局，重跑 A 的五組。

| 檢查 | 結果 |
|---|---|
| A 的結果中有變化的組 | 只有 `a_nojam`；`base`、`a_pre`、`a`、`a_nocyber` 的每個數值與修正前相同 |
| `a_pre` 為何沒變 | 對照組始終有 1,000 套以上，本來就高於 800 套門檻 |
| B、C、D 回歸 | 以修正後的程式重算三個想定 results.csv 的所有組合，1,704 個數值與既有結果完全相同 |
| 一局範例 | 推演紀錄與分數相同；JSON 只多了 B、C 實作後新增的欄位 |

| 藍方打法（紅方灰色地帶） | 對照 `a_pre` | `a_nojam` 修正前 | `a_nojam` 修正後 | 想定 A |
|---|---|---|---|---|
| 均衡 | 86.9% | 88.5% | 84.4% | 83.7% |
| 重 GEO | 88.4% | 87.7% | 87.0% | 86.7% |
| 重低軌 | 73.4% | 74.9% | 72.6% | 71.5% |
| 重修纜 | 81.6% | 81.0% | 79.8% | 79.4% |

修正後 `a_nojam` 在兩種紅方策略、四種打法下都低於對照組，拆解變體可以正常解讀，結果見推演報告的「攻擊代價拆解」一節。
