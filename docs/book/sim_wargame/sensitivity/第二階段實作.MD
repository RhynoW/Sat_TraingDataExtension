## 1. 摘要

1. 新增 `Params` 結構，蒙地卡羅與新對局 API 可以覆寫 12 個示意參數與 AI 規則。預設值等於原本的常數與規則，**省略時結果與修改前逐值相同**。
2. 蒙地卡羅 API 新增 `per_game: true`，回傳每局結果，供配對差值、分位數與名次穩定度使用。
3. 新增 `docs/book/sim_wargame/sensitivity/`：32 組實驗、159,000 局，產生敏感度分析報告。
4. 介面（`games_war.js`、`games.html`）沒有修改；參數覆寫只供分析 API 使用。

## 2. 設計原則

| 原則 | 作法 |
|---|---|
| 不改變既有結果 | 預設值取自原本的常數（`A_WIPE`、`B_PNT_JAMMED`、`B_SAR_P`、`C_EVADE_DIP`）與原本寫死的數值（0.3、0.1） |
| 不改變亂數序列 | 新的機率參數為 1.0 時不抽亂數（`p >= 1.0 \|\| rng.f() < p`），所以預設情況下每局抽亂數的次數與順序不變 |
| 紅方「禁用」不浪費點數 | 禁用的行動在 `push` 時跳過，不扣點數，省下的點數照原優先序給後面的行動 |
| 紅方的認知與藍方的資料分開 | 監視資料中斷只影響藍方（看到的距離、歸因），紅方 AI 仍以「已被監視」決定出手率 |

## 3. 參數一覽

| 欄位 | 預設 | 作用 | 想定 |
|---|---|---|---|
| `a_wipe` | 0.3 | 開戰前抹除比例；未強化時每次網攻永久抹除的比例 | A |
| `red_ban` | `[]` | 紅方 AI 不得下令的行動 | 全部 |
| `b_pnt_jammed` | 0.3 | GPS 被干擾、無備援時的定位授時可用率 | B |
| `b_sar_p` | 0.8 | SAR 每次過頂成功率 | B |
| `c_p_strike` | 0.3 | 灰色地帶紅方在 10 km 內、藍方未監視時的每回合出手率 | C |
| `c_p_strike_tracked` | 0.1 | 同上，藍方已監視時（紅方風險偏好） | C |
| `c_track_p` | 1.0 | 監視資料每回合有效的機率 | C |
| `c_attrib_p` | 1.0 | 有效追蹤下攻擊被歸因的機率 | C |
| `c_evade_p` | 1.0 | 規避成功率 | C |
| `c_evade_dip` | 0.7 | 規避次回合的 GEO 服務比例 | C |
| `d_img_factor` | 1.0 | 自有光學衛星被毀後，商業影像的偵察效能比例 | D |
| `d_red_pref` | `"adaptive"` | 紅方目標偏好；`"isr"` 為不論藍方有無備援一律打光學衛星 | D |

## 5. 驗證

| 檢查 | 結果 |
|---|---|
| 編譯 | `cargo build --release` 無警告 |
| 回歸：省略 `params` | 以新程式重算想定 A、B、C、D 四份 results.csv 的所有組合：2,464 個數值與既有結果完全相同 |

## 6. 實驗設計

完整清單見 `run_sensitivity.py` 的 `experiments()` 與 `run_meta.json`。

| 想定 | 實驗 | 紅方 |
|---|---|---|
| A | 對照組；抹除 15%／30%／60%；三種頻寬手段都不用、只切纜、只干擾、只網攻 | 兩種 |
| B | 基準；紅方不干擾 GPS／SAR；定位授時 10%／60%；SAR 50%／95%；權重格點重算（不另跑） | 兩種 |
| C | 基準；只接近；紅方風險偏好 5%／30%（只有灰色地帶）；監視有效 70%／40%；歸因 50%；規避成功 80%／50%；規避次回合服務 85%／50%；保守組合 | 兩種（風險偏好除外） |
| D | 基準；不用反衛星；紅方調整目標＋影像 40%；紅方一律打光學衛星＋影像 100%／70%／40% | 兩種 |

## 7. 已知限制

1. 新增的隨機判定（監視中斷、歸因、規避失敗）會讓亂數序列錯開，該設定下的配對差值精確度下降（例如想定 C 監視有效 70% 時半寬由 ±0.3 變 ±0.5）。
2. 紅方「禁用」只是把點數讓給後面的行動，不是重新最佳化；想定 B 的「不干擾」對照因此會轉向通信攻擊。
3. 參數覆寫只開放給 API，介面沒有對應控制項。
4. 審查建議中尚未處理的項目列在敏感度分析報告的「未處理的審查建議」一節。
