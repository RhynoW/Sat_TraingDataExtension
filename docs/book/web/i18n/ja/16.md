# 第16章　ルーティング、格下げと適用外の場面

> *この日本語版は、繁体字中国語原稿（v1.3、2026-11-19）をAIの支援により翻訳したものです。内容に相違がある場合は中国語の原文が優先します。*

## 章の導入

2010年4月5日前後、IntelsatのGalaxy 15が地上からのコマンドに応答しなくなった。もともと西経133度付近（報道による）に位置していたが、その後、静止軌道帯に沿って東へ漂流し始めた。技術者は15万～20万回のコマンドを送ったが、復旧させることはできなかった。

厄介なことに、それは死んでいなかった。通信ペイロードは通常どおり動作し、受信した信号を何でも中継し、アンテナも地球を向いたままであった。行く手には、全米各地にデジタルケーブルテレビ番組を届けるSESのAMC-11があった。SESは衛星を移動させ、Intelsatはメリーランド州Clarksburgにある19メートルのアンテナを使ってエネルギーをAMC-11に集中的に送り込んだ。6月1日、Intelsatはそれが通過し、顧客の信号が途切れなかったことを確認した。

この漂流は8か月以上続き、十数機のCバンド衛星のそばを通過し、計15回のフライバイ回避が実施された。12月に電池が尽きて機器がリセットされ、ようやく再びコマンドを受け付けるようになった。故障審査は後に、静電気放電が搭載ソフトウェアを狂わせたと結論づけ、太陽活動の関与は否定した。

外から見ると、その軌道データは奇妙ではなかった。位置は予測可能で、信号は送信されており、姿勢は安定していた。データが正常に見えるとき、システムはこの案件を人に引き渡すべきだとどうやって知るのか。

ルーティングと格下げの目的は、すべてのデータを同じモデルに詰め込むことではなく、次のことを決めることにある。特定のデータ条件、特定の軌道域、特定の任務の下で、システムがどの経路をたどり、どのレベルの判断を出力し、いつ人手による再確認に引き渡すか。本章はCase 24を主要事例として、事例横断的な分解能の限界を、ルーティング、重みの引き下げ、人手による再確認、データ高度化の要件へと変換する。¹

本プロジェクトのシステムを例にとると、最終報告書は二つの組み合わせ方を区別している。アプリの「統合検知サマリー」はまず再突入ゲートを通り、次に固定ルール（カタログ名が「STARLINK」で始まるか）で振り分ける。StarlinkはModel 1と融合スコアラーが主判定し、Starlink以外はNRLMSIS抗力残差が主判定し、Model 2は裏付けにとどまる。これは参考表示にすぎず、候補イベントを決定しない。一方、正式なR7単一衛星レポートはすべての衛星に同じフローを適用し、L1ルールが候補イベントを決定し、その他の手法は証拠等級にのみ影響する。理由は、正式な報告書はどの衛星についても一件ずつ再現できなければならず、機械学習モデルはStarlinkのみで訓練されているため、他の衛星に用いた場合は検証できないからである。⁴

## 学習目標

- ルーティング、格下げ、適用外の場面の違いを理解する。
- 事例横断的な分解能の限界がどこから来るのかを理解する。
- Case 24を通じて、ノイズフロア、大気抵抗の状態、観測の死角、逆推定の天井を知る。
- ルーティング規則を万能の解とみなすことを避ける。
- 格下げの結果をすべての場面に外挿することを避ける。

## ルーティングと格下げは何を問うのか

ルーティングと格下げが答えるべき問いは次のとおりである。

> **この場面を、システムはどう処理すべきか？**¹

答える前に、まず比較の基準を確認しなければならない。同じルーティング規則でも、軌道域、データ条件、任務が異なれば、その意味はまったく異なりうる。

本書は、ルーティングと格下げについて少なくとも三種類の出力を区別することを勧める。

| 出力 | 意味 | 主な限界 |
|---|---|---|
| ルーティング | システムがどの経路を使うべきか。 | すべての経路が検証済みであることを表すものではない。 |
| 格下げ | システムが信頼度を下げるか保留すべきか。 | すべてのリスクが排除されたことを表すものではない。 |
| 適用外 | システムがモデルを使うべきでない。 | すべての適用可能性が排除されたことを表すものではない。 |

三者は階層が異なり、互いに代替することはできない。判読時には、表の限界欄に従ってそれぞれ説明すべきである。

最終報告書のR7は、いくつかの具体的な格下げルールを定めている。7日以上のTLEの空白をまたぐイベントは最高でもE2とする。「上がってまた戻る」反跳型のイベントはDとし、まず元のTLEとカタログを照合する。50キロメートル以上の単発の跳躍も検出はするが、先にカタログの照合を促す。Starlink以外の衛星で、機械学習の補助によってのみE3の条件を満たすイベントは「E2（ML補助）」に改める。Starlink以外の衛星における融合スコアラーの閾値超過時点は、真値評価ですべて誤報であったため、低信頼度レビュー項目に挙げない。データ監査でsuspectとされたTLEは、検出層で重みを下げる。⁴

**コラム：DMSP F13とNOAA-16の電池による分解（2015）**

2015年2月3日、1995年に打ち上げられたDMSP F13で電力異常が発生し、回転を始め、その後分解した。米空軍の調査は、電池充電器のハーネスの故障により短絡・過充電が起こり、最終的に電池が破裂したと結論づけた。統計上、147個の追跡可能な物体が生じた（2月末の最初の公表では43個）。同年11月25日には、退役済みのNOAA-16が841 × 857キロメートルの軌道で分解し、NASAの掲載時点で136個がカタログ化されていた。電池の故障の可能性があると判断された。この種の軌道の急変はマヌーバではなく、適用外と判定して人手に回すべきである。静止軌道での同種の例は第9章のIntelsat 33eを参照。

### 事例の位置づけ

Case 24の問いは「TLEは結局どこまで細かく見えるのか？」である。事例横断的にまとめた物理的分解能の限界の総括表によって、本プロジェクトが四つの異なる角度のいずれにおいても同じ壁に突き当たったことを示す。²

Case 24は本章におけるルーティングと格下げの事例であり、システム全体の完全な検証ではない。その結論はやはり前述の各層と併せて判読しなければならない。

### ノイズフロア

Case 24は、ノイズフロアを事例横断的な分解能の限界の一つに挙げる。ノイズフロアは軌道高度によって変化し、データそのものの物理的性質に属するため、アルゴリズムの改良では解決できない。ノイズフロアの手法は確立されたが、完全な検証はまだ完了していない。²

Case 18を例にとると、推進装置を持たず自らマヌーバを行わない8機の受動測地衛星を用いて、800–19,126キロメートルの軌道高度にわたりTLEの軌道長半径のノイズを走査した。この種の衛星はそれ自体が静穏であることが保証されており、ノイズフロアを測定する最もクリーンな対照群である。²

したがって次のことを明記すべきである。結果をすべての高度に外挿すべきではなく、配備時には実際の条件に応じて再検証しなければならない。

### 大気抵抗の状態

Case 24は、大気抵抗の状態を事例横断的な分解能の限界の一つに挙げる。その時点の大気抵抗の状態が検出閾値を支配しており、適応的閾値で緩和はできるが、解消はできない。抗力残差の手法は確立されたが、完全な検証はまだ完了していない。²

最終報告書のL1ルールはまさにこの方法をとっている。P2は高度に応じて軌道長半径の閾値を設定し（400キロメートルで約2.0キロメートル、700キロメートル以上で0.4キロメートル）、P5はその日のF10.7に応じて引き上げる（200 sfuで1.6倍、上限1.8倍）。抗力残差は現在0.3キロメートルの固定閾値を用いており、400キロメートル以下では誤報が多すぎ、600キロメートル以上では保守的すぎる。高度に応じて調整する案は、サンプル外検証ですべての高度で目標を達成したものがまだなく、現時点では方向性の提案にとどまる。⁴

この行の証拠はCase 17によるものである。FORMOSAT-7／COSMIC-2の実際のTLEを背景に、15,775回のマヌーバ注入試験を行い、478組の衛星×窓をカバーした。元の更新頻度では、低抗力状態で50メートルを注入すれば既に99%の検出率があるが、高抗力状態では約90%に達するのに150–200メートルを要する。これらは固定仮定下の合成注入の結果であり、実際のマヌーバの検出率ではない。²

したがって次のことを明記すべきである。結果をすべての軌道に外挿すべきではなく、配備時には実際の条件に応じて再検証しなければならない。

**コラム：Aeolusの支援付き再突入（2023）**

2023年7月、欧州宇宙機関のAeolusは完全な制御再突入を行うには燃料が足りず、代わりに残りの燃料を使って、ESAが初の「支援付き再突入」と呼ぶものを実施した。まず約280キロメートルまで自然に減衰させ、7月24日から段階的に軌道を下げた。280キロメートルから250キロメートルへ、さらに230キロメートルへと下げ、7月28日の最後のマヌーバでは150キロメートルから120キロメートルへ下げる計画で、その夜に南極上空で再突入した。本書の手法で振り返れば、このTLEは自然減衰の中に一連の能動的な軌道降下が挟まったものであり、この二種類の降下を見分けることこそ再突入ゲートの役割である。最終報告書の例では、廃棄のための軌道降下を行ったStarlinkの近地点は階段状に下がり、再突入ゲートは発動せず、マヌーバは正常に検出された。逆に、ゲートがいったん発動するとマヌーバ数は0と出力され、能動的な軌道降下も一緒に見落とされる可能性があるため、ゲートの判定はルール層の候補イベントと併せて見る必要がある。⁴

### 観測の死角

Case 24は、観測の死角を事例横断的な分解能の限界の一つに挙げる。ここでいう死角とは、信号が監視対象の変量に含まれていないことを指す。本プロジェクトが監視する中核変量は軌道長半径である。² 最終報告書によれば、R7のL1はさらに|Δi| > 0.02°と|Δe| > 0.001を独立した標記として用いるため、より大きな傾斜角や離心率の変化は捉えられる。しかし沿軌道方向の位相の変化や、傾斜角の閾値を下回る軌道面に垂直な成分では、軌道長半径もこの二つの量もほとんど動かない。昇交点赤経の残差は、アブレーションとFORMOSAT-7（福衛七号）の真値による検証で誤報を増やすだけであったため、判定に含めていない。⁴ このようなマヌーバは構造的な死角であり、閾値の調整で解決できる問題ではない。

したがって次のことを明記すべきである。データ品質と観測窓の手法が扱うのはデータの欠落であり、この種のマヌーバはカバーできず、別の変量を監視する必要がある。結果をすべての観測条件に外挿すべきではなく、配備時には実際の条件に応じて再検証しなければならない。

### 逆推定の天井

Case 24は、逆推定の天井を事例横断的な分解能の限界の一つに挙げる。これはCase 10でTLEから大気密度を逆推定しようとした試みに由来する。同事例は目標に達しなかったことを率直に認めており、精密エフェメリスに切り替えても密度推定には回避できないばらつきが残る。上限はTLEの欠陥だけでなく、逆推定手法そのものから来ている。²

したがって次のことを明記すべきである。これは方法論上の上限であり、データ源を替えても完全には解消できない。結果を他の逆推定問題に外挿すべきではなく、配備時には実際の条件に応じて再検証しなければならない。

### 安全保障上の含意

Case 24の示唆は次のとおりである。

> **TLEの分解能の限界は単一の数値ではなく、分けて扱わなければならない一組の限界である。**²

実務上は、ノイズフロア、大気抵抗、観測の死角、逆推定の天井を分けて扱い、それぞれの適用範囲と限界を明記する。未検証の結果は保持したうえでその旨を注記する。ルーティング規則は万能の解ではなく、新たな配備条件に移る際には再検証が必要である。

**コラム：IRASとGGSE-4の会合（2020）**

2020年1月29日、IRASとGGSE-4はピッツバーグ上空約900キロメートルで会合し、相対速度は秒速14.7キロメートルであった。メディアの伝えるところによれば、LeoLabsは当初、衝突確率を約1/100と見積もった。1月28日の更新で約1/1000に下がったが、29日にGGSE-4に長さ約18メートル、向き不明の安定化ブームがあることが判明し、合成ハードウェア半径を5メートルから10メートルに引き上げたところ、確率は再び約1/20に上昇した。両者は最終的に無事すれ違った。同じ会合でも、数値は仮定に応じて二度ひっくり返った。出力は仮定とともに説明しなければならない。

## ルーティングと格下げの設計

本書は、ルーティングと格下げに次の事項を含めることを勧める。

- ルーティング条件と優先順位。
- 格下げ条件と信頼度レベル。
- 人手による再確認の条件。
- データ高度化の要件。
- 既知の失敗シナリオ。
- バージョンと回帰テストの結果。

これらの項目があれば、分析者は判断の過程を再構成でき、目にするのは赤いフラグ一つだけではなくなる。

**コラム：Envisat通信途絶後の集中観測（2012）**

2012年4月8日、欧州宇宙機関のEnvisatが突然通信途絶となった。状態を判断するため、フランスのCNESは4月15日にPleiades衛星の向きを変え、約100キロメートル離れた位置からEnvisatを撮影して太陽電池パネルの向きを確認した。ドイツFraunhofer FHRのTIRA画像レーダーは本体、太陽電池パネル、レーダーアンテナを捉え、複数のレーザー測距局が軌道の安定を確認した。5月9日、ESAはミッション終了を宣言し、三つの推定シナリオを挙げるにとどまった。軌道データが答えられるのは「それがどこにあるか」だけである。「それに何が起きたか」に答えるには、データ源を高度化しなければならない。

**コラム：AMC-9とTelkom-1の静止軌道異常（2017）**

2017年6月17日、SESはAMC-9との通信を失い、衛星はその後西へ漂流し続けた。ExoAnalyticの望遠鏡は6月25日、いくつかの比較的大きな破片が本体から分離するのを捉えた。8月25日には、インドネシアPT TelkomのTelkom-1で主アンテナの指向に問題が生じ、5日後に回復不能と判断された。ExoAnalyticは同様に、いくつかの大きな破片を観測した。いずれの事象も原因は確定していない。運用者がテレメトリを失ったとき、独立した商業光学観測が穴を埋める目となった。静止軌道のTLEの更新頻度は、破片が剥がれ落ちるペースに追いつけない。

## ルーティング・格下げと他の層の役割分担

ルーティングと格下げはルール層に代わるものではなく、統計層に従属するものでもない。ルーティングと格下げは適用外の場面の処理を担う。ルール層は説明可能な候補イベントと抑制理由を提供し、統計層、物理残差、融合スコアラーは補助チャネルとして、イベントの前後にも反応があるかを確認するものであり、証拠等級にのみ影響する。⁴

| 問い | 優先して用いるのに最も適した構成要素 |
|---|---|
| 既知の閾値を超えているか？ | L1 ルール層。 |
| 直近の平常から逸脱しているか？ | L2 統計層。 |
| 複数チャネルが共に支持しているか？ | 補助チャネルの照合（L2、抗力残差、ML ウィンドウモデル、融合スコアラー）。証拠等級にのみ影響する。 |
| 抗力や再突入で説明できるか？ | 物理・適用性処理。 |
| データは判断に足りるか？ | 品質ゲート。 |
| この場面をどう処理すべきか？ | ルーティングと格下げ。 |

この表は本書による工学上の役割分担の整理である。各チャネルは並列に計算できるが、正式な報告書の判定順序は最終報告書の R7 フローによって確定しており、他のシステムは配備条件に応じて調整してよい。最終報告書の R7 単一衛星レポートのフローでは、候補イベントは L1 ルールのみによって決定される。その他の要素は証拠等級にのみ影響するか、L1 が標記しなかった時間帯を低信頼度レビュー項目として挙げ、分析者の判読に委ねる。⁴

## 本章のチェックリスト

- [ ] ルーティングと格下げが扱うのは適用外の場面であり、完全な判読に代わるものではないこと、ルーティング規則はデータ品質、ルールによる抑制、統計層、物理残差、融合判定と併せて判読しなければならず、単一のルーティング規則で完全な証拠の連鎖を代替することはできないことを説明できる。
- [ ] 事例横断的な分解能の限界を分けて扱わなければならない理由を説明できる。
- [ ] ノイズフロア、大気抵抗、観測の死角、逆推定の天井を区別し、四者を混同しないことを説明できる。
- [ ] 各ルーティング・格下げ規則について、適用範囲と限界を明記できる。
- [ ] システムがある場面を人手による再確認へルーティングしたり適用外と判定したりすることは、データが「平常からの逸脱」を示しているか、モデルの適用範囲を超えていることを意味するにすぎず、マヌーバの確認と同じではなく、まして敵意や違反と同じではないことを説明できる。
