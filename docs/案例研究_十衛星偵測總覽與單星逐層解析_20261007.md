## 一、為什麼要做這份文件

期末報告的核心指標（ROC-AUC、召回率等）是把成千上萬筆資料壓縮成幾個數字，容易讓讀者看不到「系統實際上是怎麼判斷一顆衛星的」。本文件反過來，從 10 顆真實衛星的偵測結果出發，再挑一顆衛星，把 Web App（`maneuver_app_2026November.py`）背後三層（規則層、統計層、機器學習層）從頭到尾怎麼判斷講清楚。

### 2.3 如何解讀這張表（以白話說明每一列）

- **路由主判**：系統先看這顆衛星屬不屬於 Starlink。屬於 → 用訓練在 Starlink 上的 Model 1（LightGBM）＋融合評分器當主判；不屬於（含福衛、太空站、QZS-7、Yaogan、Jason-3 等）→ 改用不限軌域的 Model 2（無監督）＋ NRLMSIS 物理阻力殘差當主判。這就是為什麼表中只有三顆 Starlink 有「融合最高機率」接近 0.9 以上，其餘衛星的判斷主要看「Model 2 異常次數」。
- **Model 2 異常次數隨 TLE 筆數與歷史長短變化是正常的**：國際太空站歷史最長（26 年、47,687 筆），異常次數也最多（644 次）；這不代表太空站「最危險」，只是因為它長年需要定期拉高軌道以抵銷大氣阻力、避開太空垃圾，样本數本身就遠多於其他衛星。
- **QZS-7 的融合旗標是 0 次**：因為它是 GEO、非 Starlink，融合評分器／Model 1 根本不是它的主判路徑；它真正的判斷依據是 16 次 Model 2 異常，這些異常對應它 2026 年發射後從 GTO 轉移軌道拉高到準同步軌道的真實公開事件。
- **福衛七號系列（44349）** 是本專案文獻中已知有長時間追蹤缺口的衛星，26 次 Model 2 異常中有多少是真機動、多少是缺口造成的資料跳變，需要搭配第六節「資料品質稽核」區塊的 `quality_flag` 一起看，不能只看這張表的數字。

## 三、單星逐層解析：STARLINK-37471

本節選擇 STARLINK-37471（NORAD 68802）作為完整案例，因為它是本專案文獻中記錄最完整的一次真實大型軌道爬升事件，適合示範系統從「一筆一筆的 TLE 差值」到「最終判定」的完整邏輯鏈。

### 3.1 製作過程中的一次誠實更正

本專案過去文件記載「STARLINK-37471 於 2026-06-21 09:38:42Z 執行 Δa＝+50.3 公里的大型升軌」。製作本案例時，重新查詢這顆衛星完整的 TLE 半長軸（a）時序，發現：

| 日期 | 半長軸 a（km） |
|---|---:|
| 2026-06-14 | 6797.1（爬升前） |
| 2026-06-15 | 6797.4 → 6809.6（當天開始爬升） |
| 2026-06-16 | 6820.2 → 6832.3 |
| 2026-06-17 | 6832.9 → 6841.8 |
| 2026-06-18 | 6843.8（爬升完成） |
| 2026-06-19 ～ 06-24 | 6843.6 ～ 6843.9（軌道已穩定，無進一步變化） |

**實際的軌道爬升集中發生在 2026-06-15 至 06-18（約 3 天），而不是 06-21。** 「2026-06-21 09:38:42Z」這個時間點，來自 MEME 精密星曆真值檔裡「前後兩筆取樣點」中**較晚的那一筆**（因為 MEME 真值不是每天都有，兩筆取樣相隔了近 7 天：06-14 17:39 到 06-21 09:38），真值檔把這段期間的**淨變化**（+50.3 公里）整筆記在這個區間上。換句話說：**+50.3 公里是對的，但「06-21 這個時間點發生了一次大爬升」是誤讀**——軌道在 06-18 就已經爬升完成並穩定下來，06-21 只是真值資料「剛好有一筆落在穩定期」的取樣時間。

這個更正本身也是一個有教育意義的例子：**真值資料的取樣間隔，會影響我們對「機動什麼時候發生」的直覺判斷**，使用 MEME 真值時務必注意這一點，不能只看頭尾兩個時間點就當作機動發生的精確時刻。

下文的逐層解析，改用實際可觀測到爬升訊號的時間點。

### 3.2 選定的代表性單筆轉移

在 06-15～06-18 的爬升期間，挑選單日變化量最大的一筆差值作為示範：

| 項目 | 數值 |
|---|---|
| 前一筆 TLE 時刻 | 2026-06-16 14:00:01Z |
| 本筆 TLE 時刻 | 2026-06-16 20:00:02Z |
| 間隔 | 6.0 小時 |
| 半長軸變化 Δa | **+7.67 公里** |
| 傾角變化 Δi | −0.0001°（幾乎無變化） |
| 離心率變化 Δe | +0.000038（幾乎無變化） |
| J2 修正後 RAAN 殘差 ΔΩ_res | −0.0018°（遠低於 0.10° 門檻，無異常） |
| 當時 B* 係數 | −0.115 |
| 當時 F10.7 太陽通量 | 116.6 sfu |

> 📘 **為什麼只有半長軸明顯變化**：這是一次「拉高軌道」的機動，火箭/電推系統只在軌道平面內加速，不改變軌道傾角或升交點位置，所以 Δi、Δe、ΔΩ 幾乎不動，訊號集中在 Δa 一個通道——這正是軌道力學教你「沿軌方向推力只改變軌道大小」的直接驗證。

### 3.3 Layer 1：規則層怎麼看這筆資料

六條規則逐一檢查這筆 **+7.67 公里 / 6 小時** 的變化：

| 規則 | 判定 | 為什麼 |
|---|---|---|
| P1（單調衰減抑制） | 不抑制 | Δa 是正值（往上升），完全不符合「持續小幅下降」的大氣衰減特徵，P1 不會把它當成自然衰減 |
| P2（高度自適應閾值） | **觸發** | 此高度（約 465 公里）的門檻約 1.4～1.5 公里，+7.67 公里遠遠超過 |
| P3（B* 抑制） | 不抑制 | B* 係數不足以用阻力解釋這麼大的上升量 |
| P4（多窗口補充） | **觸發** | 短窗重掃同樣抓到這筆跳變 |
| P5（F10.7 自適應倍率） | **觸發** | 當時太陽通量 116.6 sfu，門檻依此微幅上調後，+7.67 公里仍遠超標 |
| P6（星座/軌域感知） | **觸發** | 此衛星屬太陽同步帶（SSO），套用對應倍率後仍判定異常 |
| **合併結果** | **✅ 判定為機動候選** | 4 條規則同時觸發，無抑制規則介入 |

**白話總結**：規則層的判斷邏輯很直接——「這個高度、這個太陽活動程度下，正常波動大概是多少，你超過了多少倍」。+7.67 公里遠遠超過任何一條規則的容許範圍，所以四條規則一致判定為可疑。

### 3.4 Layer 2：統計層怎麼看

對整段半長軸時序跑四種統計方法，取這筆轉移對應時刻附近的分數：

| 方法 | 分數 | 是否觸發事件 | 白話意義 |
|---|---:|---|---|
| CUSUM（累積和） | 於此刻歸零後重新累積 | ✅ 觸發 | 偵測到「持續性位移」的起點 |
| BOCPD（貝氏線上變點） | 0.055～0.07（偏低） | ❌ 未觸發 | 這個方法看的是「當下機率」，對連續多日的漸進爬升不如對單一瞬間跳變敏感，這次沒搶先反應 |
| SSA（奇異譜分析殘差） | 61.2（遠高於平常） | ✅ 觸發 | 把「正常趨勢」濾掉後，剩下的突兀程度非常明顯 |
| 3σ-MAD（同儕比較） | 223.1（遠高於門檻 3） | ✅ 觸發 | 跟其他衛星、跟自己過去比，這筆差值都是異常中的異常 |

**白話總結**：四個方法裡有三個（CUSUM、SSA、MAD）都明確觸發，只有 BOCPD 這一個方法沒有在這一刻搶先反應——**這正是用四種方法而不是只用一種的原因**：單一方法可能會漏掉，多種方法交叉比對比較不容易被騙。

### 3.5 Layer 3：機器學習層怎麼看

**Model 1（監督式 LightGBM，逐窗口判斷）**：

| 項目 | 數值 |
|---|---|
| 這一刻的機動機率 | 61.2%（操作門檻 48.2%，**超過門檻**） |
| 同時段阻力殘差（扣除大氣阻力後還剩多少） | 7.68 公里（遠超過 0.30 公里的「可能是阻力」門檻） |
| **判定** | **✅ 標記為機動** |

**融合評分器（整合 CUSUM/BOCPD/SSA/MAD + 阻力殘差五個通道，取前後 24 小時窗彙整）**：

| 時刻 | 融合機率 |
|---|---:|
| 2026-06-16 20:00（即本筆轉移當下） | 9.5%（偏低） |
| 2026-06-19 06:00（約 2.5 天後） | **87.4%**（操作門檻 65.9%，**超過門檻**） |

> 📘 **為什麼融合評分器不是在事件當下反應最強**：融合評分器看的不是單一時刻，而是「前後 24 小時這個窗口整體有多異常」。爬升當下（06-16 20:00）只是多日連續爬升的其中一步，單獨看這一刻其實不特別突出；要到整個爬升過程累積得差不多、訊號在窗口內達到最濃縮的程度（06-19 清晨），融合分數才衝過門檻。這說明融合評分器擅長抓「持續一段時間的異常模式」，而不是只看瞬間的單一數值——跟 Model 1 逐窗口判斷（在機動發生的當下就反應）剛好是互補的兩種節奏。

### 3.6 最終：系統給出的總結

把以上所有層級的意見彙整起來，App 畫面最上方的「🎯 統一偵測摘要」卡片會顯示：

- **軌域 · 域**：LEO · Starlink（屬於訓練分布內，用最靈敏的 Model 1 + 融合評分器路線）
- **路由主判**：Model 1 (LightGBM) + 融合評分器
- **融合旗標**：這顆衛星整段歷史中共 43 次（此次爬升事件即貢獻其中數次，含 06-19 清晨那次高分警報）
- **融合最高機率**：0.912（全歷史最高點，出現在另一段也屬於明顯機動的時期）
- **Model 2 異常次數**（交叉參考）：64 次

**白話總結整個故事**：STARLINK-37471 從 2026-06-15 到 06-18 用了約 3 天時間，把軌道從約 455 公里拉高到約 465 公里（半長軸上升約 47～50 公里）。這段爬升在規則層被四條規則同時標記、在統計層被三種方法同時標記、在機器學習層的逐窗口判斷中也被即時標記；融合評分器則在爬升告一段落、累積訊號最濃縮的時間點給出全程最高分之一的警報。**四種角度幾乎一致指向同一個結論——這是一次真實的機動，不是雜訊或巧合。**
