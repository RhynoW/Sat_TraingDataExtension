## 一、資料資產分類與現況

| 類別 | 代表資產 | 現有落地位置 | 現況 |
|---|---|---|---|
| 原始 TLE 全庫 | `space_db.duckdb`（14GB）、`space_db_slim.duckdb` | 本機專案根目錄；slim 版另發布 HF Dataset `RhynoWu/satdashboard-db` | 本機無版本化備份；HF Dataset 為事實上的異地備份，但只含精簡版（近14天+白名單） |
| MEME 精密星曆 | `data/raw/{sat_id}/*.txt`（推估數十GB） | 本機專案根目錄，git 排除（`.gitignore`） | 無備份；來源為 SpaceX 公開 API，若對方下架歷史檔則不可回補 |
| 機動真值 | `data/meme_truth/transitions_full_*.csv` | 本機 + git 追蹤（小檔） | 隨 git 已有異地備份（GitHub） |
| 標竿/評測輸出 | `data/benchmark/*.csv` | 本機，多數已 git 追蹤 | 隨 git 已有異地備份 |
| 模型檔 | `Orbital_Maneuver_V2/models_*/*.pkl` | 本機，部分 git 追蹤（依 `.gitignore` 而定） | 部分已備份，部分（如大型 pkl）可能被排除，需逐一確認 |
| 報告/論文/程式碼 | `docs/*.md/.docx`、全部 `.py` | git（GitHub `RhynoW/...` + 本機） | 已有異地備份（GitHub） |
| SatDashboard 應用資料庫 | `scenario04/DB/*.duckdb` | 獨立 repo（`scenario-advanced01`），另發布 HF Space/Dataset | 已有異地備份（HF） |

**結論**：文件/程式碼/小型結構化資料（真值、標竿輸出）已透過 git/GitHub 取得異地備份；**風險集中在兩個大型二進位資產：`space_db.duckdb` 全庫、`data/raw/` 逐分鐘 MEME 星曆**——兩者體積過大不適合進 git，目前僅存在於本機單一位置，無異地備份。

## 二、備份規範（新增規則）

| 資產 | 備份策略 | 頻率 | 保存份數 |
|---|---|---|---|
| `space_db.duckdb` 全庫 | 精簡版（slim，近14天+白名單）持續發布 HF Dataset `RhynoWu/satdashboard-db`（已執行）；**新增**：每季對全庫做一次完整快照，上傳至獨立雲端儲存（如另一 HF private dataset 或外接硬碟），標記日期 | 精簡版隨每日管線自動更新；全庫快照每季 1 次 | 精簡版僅保留最新版；全庫快照至少保留最近 2 季（供回溯比對用） |
| `data/raw/` MEME 星曆 | **新增**：每月匯出一次已下載範圍之壓縮封存（tar/zip），存至外接儲存或雲端物件儲存；封存前先執行去重（同顆衛星重疊時間段僅留最新） | 每月 1 次 | 至少保留最近 3 個月封存；若儲存成本允許，年度封存永久保留（此為研究不可回補之外部資料） |
| 模型檔（`.pkl`） | 每次重訓練後，連同其 `feature_names.json`/`threshold.json` 一併納入 git（若檔案 <100MB）或另存版本化清單（若超過 git 建議上限） | 隨重訓練事件 | 保留最近 3 個版本，供回溯比較模型演進 |
| 報告/程式碼 | 沿用現行 git 雙遠端（GitHub `origin`）流程 | 隨每次 commit | git 歷史即為版本化備份，無需額外規範 |

**執行方式建議**：新增一支 `backup_snapshot.py`（比照 `run_drag_residual.py`/`run_comspoc_pipeline.py` 之 CLI+`satdet.record()` 慣例），可先建立最小可行版本（僅涵蓋 slim DB 快照上傳），全庫/MEME 封存因體積與外部儲存帳號需求，建議列為期末報告承諾之「規範已定義、執行需另行提供儲存空間預算」，避免在無實際儲存資源的情況下承諾無法履行的自動化排程。

## 三、保存年限規範

| 資產 | 保存年限 | 理由 |
|---|---|---|
| 原始 TLE 全庫、MEME 星曆 | **永久保留**（不主動刪除） | 兩者皆為外部來源、不可回補（TLE 隨時間被覆寫/下架，MEME API 僅保留有限歷史窗），且為本研究之真值/驗證基礎，未來復現或延伸研究皆需要 |
| 標竿/評測輸出、真值 CSV | 永久保留（隨 git） | 檔案小，成本可忽略；為研究結論之直接證據鏈 |
| 模型檔 | 至少保留 3 年（契約結案後） | 供未來稽核或延伸研究使用；契約通常有結案後之資料保存年限要求，3 年為常見基準，如委託單位另有規定以其為準 |
| 期中/期末報告、程式原始碼 | 永久保留 | 契約交付物本身 |
| 暫存/中繼檔（如 `*.partial.csv` checkpoint、螢幕截圖等） | 30 天後可清除 | 純執行過程之暫存產物，無獨立留存價值 |

> **待委託單位確認**：國家太空中心對本案資料保存年限若有明文規定（如政府採購案常見之「結案後保存 5 年」等），應以委託單位規定為準，本規範僅為未接獲明確指示前之工作假設。
