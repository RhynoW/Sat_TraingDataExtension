# STORM-AI 實測密度 vs 本專案 NRLMSIS 阻力殘差口徑：驗證與比值修正試驗

日期：2026-09-28　位置：`research_202609/stormai/`（本研究只寫入此資料夾，未改動任何專案檔案）

## 0. 結論（先講）

1. **專案現行程式有一個沒被發現的無效改良**：`atmospheric_drag.py`（2026-09-09 版）辛苦組出的 3 小時 ap(7) 陣列，pymsis 根本沒用到。pymsis `calculate()` 預設 `geomagnetic_activity=1`（NRLMSIS 開關 9=1）只讀 ap[0]（日均 Ap）；要讀 ap[1:7] 必須傳 `options=pymsis.msis.create_options(geomagnetic_activity=-1)`。本研究實測：預設開關下傳 ap=[100,10,…] 與 ap=[100,400,300,…] 密度完全相同（2.225e-12）；開關 −1 才分別得 1.34e-12 與 4.59e-12。另外專案文件寫 NRLMSIS-00，但 pymsis 0.12 預設 `version=2.1`，實際跑的是 **NRLMSIS 2.1**。
2. **本專案口徑最大的誤差不是 Ap 解析度，而是「單點取樣」**：原版 lat=lon=0 讓地方時＝UTC 時，密度隨 TLE epoch 的時刻畫出 2–3 倍的日夜差；現行版改星下點也一樣是單點。與 STORM-AI 實測「軌道平均密度」比，單點口徑經 B_eff 校準後仍有 rmse_ln 0.42–0.51（相對 47–72%）；改成沿軌道 18 點平均（P2）降到 0.15（16%）。
3. **磁暴期低估倍數**（以 B_eff 式校準後的中位數）：按 Dst 分級，intense（−100～−250 nT）1.20–1.34×、super（<−250）1.26×（軌道平均 P2）～1.62×（專案原版 P0）。Gannon 2024-05-11 主相 6–12 小時內約 1.35–1.5×（相對暴前基準約 1.8–2×）；但**恢復期（05-11 18h 起一天）MSIS 反而高估**，真值/模型 0.60–0.72。整體積分後 MSIS 對 Gannon 三天的總阻力並沒有明顯低估，是「時間輪廓」錯：主相太低、恢復太高。
4. **比值修正模型（LightGBM，訓練 ≤2022、驗證 2023、測試 2024）**：對單點口徑 P1 的修正把測試集相對 RMSE 從 71.9% 降到 21.8%（−70%，主要是學會了單點→軌道平均的幾何修正）；對軌道平均 P2 從 31.0% 降到 20.4%（−34%），Gannon 期間 −30.5%、2024-10 磁暴 −43%；加 OMNI2（Dst/AE）研究版 Gannon −46.8%。與 STORM-AI 冠軍（−67.7% 全期、−34.7% Gannon，任務是 3 天預報）量級相近。但模型對 Gannon 主相低估／恢復期高估的輪廓幾乎沒有改善。
5. **代回 drag_residual（2024-05 Gannon，93 顆非機動物件、1,794 個磁暴期轉換）**：**0.3 km 閘門下所有變體誤報都是 0**（原版、現行、修開關、ML 修正、軌道平均積分、實測密度 oracle 都一樣；平靜期 5,862 個轉換也是 0），Model 2 旗標同樣全部為 0；注入 ±0.4～±1.0 km 階躍的召回在所有變體都 ≥99.7%。原因是這批物件近地點 ≥441 km，Gannon 期間單一轉換實測 |Δa| 最大只有 0.255 km，現行殘差最大 0.152 km，離閘門還有 2 倍餘裕，**「磁暴誤判成機動」在本樣本中重現不出來**。差異只出現在閘門以下：**軌道平均＋逐時積分（V2）把磁暴期殘差 RMS 從 18.1 m 降到 9.7 m（−46%）、最大值 152→66 m；0.1 km 敏感度門檻的誤報 6→0**；再乘 ML 比值（V2M）只多降到 8.9 m，GRACE-FO 上 6.1 m 已和實測密度 oracle（6.7 m）相當。drop-in 的 V1M（單點×ML）在磁暴期反而沒有改善（16.1 m）。
6. **建議**：現階段**不建議**把 ML 比值修正併入正式流程（在 0.3 km 閘門下改善為 0，平靜／磁暴都一樣）。值得做的是兩個低成本的物理修正：(a) 修 pymsis 開關（一行，讓 3h ap 真正生效）；(b) `density()` 改成沿軌道平均＋逐時積分 TLE 區間。這兩項合計就拿到絕大部分增益，不必引入 ML 依賴。若要降閘門（例如 0.1 km）或擴大到 <400 km 的 VLEO／Starlink 低殼層，才值得再評估 ML 修正（§6）。

## 2. 方法

### 2.1 口徑定義（`sa_common.py`、`s2_msis_compare.py`）

| 代號 | 定義 | 對應 |
|---|---|---|
| P0 | 單點 lat=lon=0、ap(7) 全填日均 Ap、高度 a(1−e)−6378.137 | 專案 2026-09-09 前原版 |
| P1 | 單點星下點 lat/lon、傳入 3h ap(7) 但 pymsis 預設開關忽略 → 實質仍是日均 Ap | **專案現行寫法原樣** |
| P0s / P1s | 同 P0 / P1，但開關 9=−1 讓 3h ap(7) 真正生效 | 2026-09-09 改良的「原本意圖」 |
| P2 | 沿當刻整圈軌道 18 點取 MSIS 平均、WGS84 大地高、3h ap(7) 生效、F10.7 取前一日 | 建議的物理改良版（與 STORM-AI 真值同口徑） |
| P2d | 同 P2 但開關 9=1（只用日均 Ap） | 分離「軌道平均」與「3h Ap」兩效應 |

每個有真值的整點（453,628 個有效整點；6 顆衛星）計算五種密度；真值取該小時 10 分鐘值均值。
評估兩種誤差：**absolute**（ρ_true/ρ_model）與 **calibrated**（再除以逐衛星 90 天滾動中位數，模擬 `drag_residual` 的 B_eff 中位數自校準——常數倍率會被吸收，造成誤報的是相對平日的偏離）。

### 2.2 比值修正模型（`s4_ratio_model.py`）

LightGBM 迴歸 y=ln(ρ_true/ρ_base)，nowcast（只用 ≤t 的指標；本專案是事後偵測，不需 3 天預報）。
特徵皆可由 Celestrak SW＋TLE 取得：3h ap 滯後 0–24h（9 個）、24–48/48–72h 均值、24h max/sum、F10.7 當日／前日、F81、日 Ap 當日／前日、年週期、UTC 時、高度、星下點緯度、星下點地方時（sin/cos）、升降段、LTAN（sin/cos）、ln ρ_base。
M1：base=P1（可直接乘回專案 `density()` 單點值）；M2：base=P2；M2omni：M2＋OMNI2 Dst/AE/Bz/Vsw（研究上限，非部署）。
切分：train < 2023-01-01（391,548 點，2002-05～2022-12）、valid 2023（34,527）、test 2024 全年（27,553：SWARM-A/B/C、GRACE-FO1；含 Gannon 與 2024-10-10 磁暴）。

### 2.3 代回 drag_residual（`s5_drag_residual_test.py`）

在專案 DuckDB 的 TLE（2024-04-01～06-30，B_eff 以此期間中位數自校準）上，逐轉換計算六種殘差：

| 變體 | 密度 | 說明 |
|---|---|---|
| V0 | P0 | 呼叫 `AD.drag_residual`（不給 line1/2、關 3h）＝專案原版 |
| V1 | P1 | 呼叫 `AD.drag_residual` 原樣＝專案現行（自寫重算與其逐筆一致，assert 通過） |
| V1s | P1s | 只修 pymsis 開關（無 ML） |
| V1M | P1×exp(M1) | drop-in：只乘比值修正 |
| V2 | ∫P2 dt | 軌道平均 MSIS **逐時積分**整個 TLE 區間（ρ 不再只取 t_i 一點） |
| V2M | ∫P2·exp(M2) dt | 物理改良＋比值修正 |
| VT | ∫ρ_true dt | 只有 GRACE-FO1：STORM-AI 實測密度積分（oracle 上限） |

磁暴窗 STORM＝轉換終點落在 2024-05-08～05-15；平靜窗 QUIET＝04-01～04-14 ∪ 05-20～06-02（週均 Ap<10）。
負樣本：RB 火箭殘骸（名稱含 R/B、近地點<750 km、e<0.02，約 60 顆，被動物件最能反映磁暴阻力）、FS3 FORMOSAT-3 A–F（退役不推進）、FS7 FORMOSAT-7 六顆（2024-05 精密軌道 SP3 驗證事件皆 <50 m，遠低於閘門）、IDS operator 認證安靜區間（CryoSat-2、Sentinel-3A/B、SARAL、SWOT、HY-2C/D、Jason-3、Sentinel-6A；多在 700 km 以上）、GFO GRACE-FO 1/2。
召回：IDS 真值 2024 年 131 件機動 |Δa| 全部 0.01–0.12 km、`tle_visible_50=0`，在 0.3 km 閘門下任何變體召回都是 0/131，無法區分變體；故改用**注入法**——對每個負樣本轉換注入 Δa=±0.4/±0.5/±1.0 km 永久階躍，計 |resid+m|>0.3 的比例（磁暴窗與平靜窗分開）。另計部署中 Model 2（`model2.pkl` IsolationForest，z_drag 換成各變體殘差）的旗標數。
（未採用 2026-07-04 Ap 73 磁暴＋MEME Starlink 真值做真機動召回：MEME「none」級轉換 |Δa| 中位數即 0.45 km、且 Starlink 43% 的 8h 轉換屬中／大機動，對 0.3 km 閘門不是乾淨的對照。）

### 5.5 為什麼「磁暴誤報」沒有重現

- 這批物件近地點 ≥441 km。Gannon 期間單一轉換實測衰減 |Δa| 最大 0.255 km（中位衰減率約平日 1.7 倍，最高 2.8 倍），**就算密度模型完全不修正，殘差也不可能超過 0.3 km**。
- 依 §3 的倍數（主相被校準後低估約 1.35–1.5×）推算，要讓殘差超過 0.3 km，單一轉換的阻力衰減需要約 0.6–0.9 km，大致對應近地點 ≲350–380 km（Starlink 低殼層、VLEO、再入前物件）或 >1 天的 TLE 間隔。這個範圍本研究的負樣本沒有涵蓋，專案記錄中的「Gannon 誤判」可能出現在那裡，或出在 Model 1 機率分支而不是物理閘門本身——**需要主代理確認原始案例的衛星與高度**。

## 6. 建議與限制

### 6.1 是否併入正式流程

| 項目 | 建議 | 理由 |
|---|---|---|
| ML 比值修正（M1 drop-in） | **不併入** | 0.3 km 閘門下改善為 0；磁暴期 RMS 沒改善（16.1 vs 18.1 m），GFO 甚至變差（14.6 vs 11.7 m）；多一個 LightGBM 依賴與訓練分布外風險（訓練到 2022，SWARM/GRACE 系列高度 330–520 km） |
| ML 比值修正（M2，乘在軌道平均上） | 暫不併入，保留研究 | 在 V2 之上只多改善 0.8 m RMS；GFO 已到 oracle 水準 |
| **修 pymsis 開關**（`options=create_options(geomagnetic_activity=-1)`） | **建議修（一行）** | 目前 2026-09-09 的 3h ap(7) 改良完全無效；修好後磁暴 G4–G5 的校準後比值 1.31→1.17、super-storm Dst 1.54→1.32 |
| **軌道平均＋逐時積分**（`density()` 改沿軌道 18 點取平均、`drag_residual` 把 ρ 積分在 [t_i, t_{i+1}] 上，而不是只取 t_i 單點） | **建議做（物理改良，無 ML）** | 實測密度 rmse_ln 0.43→0.14；TLE 殘差磁暴 RMS −46%、最大值 152→66 m、0.1 km 敏感度誤報 6→0；召回不降。成本約為單點的 18×（每小時一組 ring），全庫仍在分鐘級 |

建議併入方式（供主代理實作，本研究沒有改任何專案檔）：
1. `atmospheric_drag.density()` 的 `pymsis.calculate(...)` 加上 `options=pymsis.msis.create_options(geomagnetic_activity=-1)`；同時把文件的「NRLMSIS-00」更正為 2.1（或明確傳 `version=0`）。
2. 新增 `orbit_avg_density(epoch, line1, line2)`：用 SGP4 在 t 前後半圈取 18 點（參考 `s2_msis_compare.geom_tle`），WGS84 大地高度，取平均；在 `drag_residual` 裡以逐時格點算 ρ̄，並對每個轉換區間內插平均（參考 `s5_drag_residual_test.integ`）。無 line1/line2 時退回現行單點。
3. 暫不引入 ML；若日後要降閘門到 ~0.1 km，或擴大到 <400 km 物件，再用本研究 `s4_ratio_model.py` 的 M2（或 M2omni）重訓評估。
4. 附帶發現（不影響殘差）：`drag_residual` 內 `t.astype("int64")` 在 DuckDB 的 `datetime64[us]` 欄位上得到的是微秒，`dt_s` 小 1000 倍，只被 B_eff 吸收（殘差不變），但 `attrs['B_eff']` 的數值大了 1000 倍，若有其他地方把 B_eff 當物理量用要注意。本研究 s5 第一次跑也踩到同一個坑（V2/V2M/VT 積分落到內插範圍外），已修正重跑，舊輸出存為 `logs_s5_buggy_v2.txt` 以供對照。

### 6.2 限制

- 負樣本近地點全部 ≥441 km，**沒有涵蓋最需要修正的 <400 km 區間**；0.3 km 閘門下的「0→0」不代表低軌也沒問題。
- 真值衛星只有 6 顆極軌道（i 87–89°）、高度 330–520 km；CHAMP 因軌道重建不可靠而未納入；GRACE-FO1 真值只到 2024-05-31。對低傾角（FS7 24°、Starlink 53°）的修正是外插。
- Swarm 軌道是從 ITRF 初始根數以 J2 長期項外推（每 3 天重置），平均高度誤差約數 km；GRACE 系列用 TLE＋SGP4，較準。
- 修正模型是 nowcast（因果特徵），不是 STORM-AI 的 3 天預報，兩者改善百分比不能直接比較；Gannon 主相／恢復期的時間輪廓誤差，這個模型修不掉。
- 真值時間戳相對 MSIS 約晚 2 小時（§3.1），本研究沒有平移對齊，對 calibrated 比值的影響很小。
- 召回用的是注入法（永久階躍、單點），沒有真實 >0.3 km 機動的磁暴期樣本。2026-07-04（Ap 73）＋MEME Starlink 是可行的下一步，但需先處理 Starlink 頻繁機動造成的負樣本污染。
